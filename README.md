# HelpDesk System

Информационная система управления заявками технической поддержки предприятия.

Проект разработан в рамках выпускной квалификационной работы на тему:

**«Исследование и разработка информационной системы управления заявками технической поддержки предприятия (на примере ООО «УРАЛ ТРЕЙД СЕРВИС»)».**

## Описание проекта

HelpDesk System - информационная система для регистрации, обработки, хранения и анализа заявок технической поддержки предприятия.

Система обеспечивает взаимодействие сотрудников предприятия, специалистов технической поддержки и менеджеров в рамках единого процесса обработки обращений.

Проект включает веб-интерфейс на Django Templates и Bootstrap, REST API, административную панель Django, систему email-уведомлений, статистику и средства автоматизированного тестирования.

## Назначение системы

Система предназначена для автоматизации процесса технической поддержки предприятия и позволяет:

* централизованно регистрировать обращения сотрудников;
* контролировать состояние и жизненный цикл заявок;
* назначать специалистов технической поддержки на выполнение заявок;
* фиксировать результаты обработки обращений;
* обеспечивать взаимодействие пользователей посредством комментариев;
* контролировать текущую нагрузку специалистов;
* получать статистические данные по работе службы технической поддержки.

## Роли пользователей

В системе предусмотрены три основные роли.

### Employee - сотрудник

Сотрудник предприятия является инициатором обращения в техническую поддержку.

Основные возможности:

* создание заявок;
* просмотр доступных ему заявок;
* просмотр информации о состоянии заявки;
* добавление комментариев;
* взаимодействие со специалистом технической поддержки в процессе обработки обращения.

### Support - специалист технической поддержки

Специалист отвечает за выполнение назначенных ему заявок.

Основные возможности:

* просмотр доступных заявок;
* работа с назначенными заявками;
* изменение состояния заявки в рамках предоставленных прав;
* добавление комментариев;
* фиксация результатов выполнения работ.

### Manager - менеджер

Менеджер осуществляет распределение заявок и контроль работы службы технической поддержки.

Основные возможности:

* просмотр заявок;
* назначение специалистов технической поддержки;
* контроль обработки заявок;
* изменение состояния заявок в рамках предоставленных прав;
* просмотр статистики;
* контроль нагрузки специалистов;
* управление пользователями и данными системы в пределах предоставленных полномочий.

## Жизненный цикл заявки

Обработка заявки в HelpDesk System осуществляется в соответствии с установленным жизненным циклом:

`NEW → IN_PROGRESS → WAITING → RESOLVED → CLOSED`

Статусы имеют следующее назначение:

* `NEW` - **Новая**. Заявка создана сотрудником и ожидает обработки и назначения исполнителя.
* `IN_PROGRESS` - **В работе**. Заявка принята в работу специалистом технической поддержки.
* `WAITING` - **Ожидает уточнения**. Для продолжения работы требуется дополнительная информация или действие.
* `RESOLVED` - **Выполнена**. Работы по заявке выполнены, результат ожидает окончательного подтверждения.
* `CLOSED` - **Закрыта**. Обработка заявки полностью завершена.

Изменение статуса заявки используется для контроля этапов её обработки и связано с системой email-уведомлений.

## Архитектура и структура проекта

HelpDesk System реализован как Django-проект с разделением функциональности на отдельные приложения. Такой подход позволяет разграничить ответственность компонентов системы и упростить дальнейшее сопровождение проекта.

Основные компоненты:

* `users` - пользователи системы, роли и механизмы аутентификации;
* `tickets` - создание, хранение и обработка заявок технической поддержки;
* `comments` - комментарии пользователей к заявкам;
* `statistics_app` - сбор и предоставление статистических данных по заявкам;
* `notifications` - формирование и отправка email-уведомлений;
* `config` - основные настройки Django-проекта и общая маршрутизация;
* `templates` - HTML-шаблоны веб-интерфейса;
* `static` - CSS и другие статические ресурсы веб-интерфейса;
* `tests` - автоматизированные тесты проекта.

### Структура репозитория


### Взаимодействие основных компонентов

Центральной сущностью системы является заявка (`Ticket`). Заявка создаётся пользователем, проходит установленные этапы жизненного цикла и при необходимости назначается специалисту технической поддержки.

Комментарии (`Comment`) связаны с заявками и обеспечивают взаимодействие пользователей в процессе их обработки.

Приложение `statistics_app` использует данные заявок для формирования статистических показателей, а `notifications` отвечает за отправку email-уведомлений при предусмотренных системой событиях.

Веб-интерфейс работает на основе Django Templates и сессионной аутентификации Django. Для программного взаимодействия с системой предусмотрен REST API с JWT-аутентификацией.


## Установка и локальный запуск

### 1. Клонирование репозитория

Клонируйте репозиторий и перейдите в каталог проекта:

```bash
git clone https://github.com/GalinaMordovina/Helpdesk-system.git
cd Helpdesk-system
```

Для работы с актуальной версией проекта перейдите в ветку `develop`:

```bash
git switch develop
```

### 2. Создание виртуального окружения

Создайте виртуальное окружение:

```bash
python -m venv venv
```

Активируйте его.

Для Windows:

```bash
venv\Scripts\activate
```

Для Linux/macOS:

```bash
source venv/bin/activate
```

### 3. Установка зависимостей

Установите зависимости проекта:

```bash
pip install -r requirements.txt
```

### 4. Настройка PostgreSQL

Для работы приложения требуется PostgreSQL.

Создайте базу данных и пользователя PostgreSQL, которые будут использоваться приложением.

Параметры подключения задаются через переменные окружения:

```env
POSTGRES_DB=helpdesk_db
POSTGRES_USER=
POSTGRES_PASSWORD=
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
```

Имя пользователя и пароль необходимо указать в соответствии с локальными настройками PostgreSQL.

### 5. Настройка переменных окружения

В корне проекта находится файл `.env.example` с примером необходимых переменных окружения.

Создайте на его основе файл `.env`.

Пример конфигурации:

```env
SECRET_KEY=
DEBUG=True
ALLOWED_HOSTS=127.0.0.1,localhost

POSTGRES_DB=helpdesk_db
POSTGRES_USER=
POSTGRES_PASSWORD=
POSTGRES_HOST=localhost
POSTGRES_PORT=5432

EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USE_TLS=True
EMAIL_HOST_USER=
EMAIL_HOST_PASSWORD=
DEFAULT_FROM_EMAIL=
```

Необходимо самостоятельно заполнить:

* `SECRET_KEY` - секретный ключ Django;
* `POSTGRES_USER` - имя пользователя PostgreSQL;
* `POSTGRES_PASSWORD` - пароль пользователя PostgreSQL;
* `EMAIL_HOST_USER` - адрес электронной почты для отправки уведомлений;
* `EMAIL_HOST_PASSWORD` - пароль приложения или другие учётные данные SMTP;
* `DEFAULT_FROM_EMAIL` - адрес отправителя email-уведомлений.

Файл `.env` содержит конфиденциальные данные и не должен добавляться в Git.

### 6. Применение миграций

После настройки базы данных выполните миграции:

```bash
python manage.py migrate
```

### 7. Создание администратора

Для доступа к административной панели Django создайте суперпользователя:

```bash
python manage.py createsuperuser
```

Следуйте инструкциям в терминале и задайте необходимые учётные данные.

### 8. Проверка конфигурации

Перед запуском приложения можно проверить настройки Django:

```bash
python manage.py check
```

При корректной конфигурации Django выведет сообщение:

```text
System check identified no issues (0 silenced).
```

### 9. Запуск приложения

Запустите локальный сервер разработки:

```bash
python manage.py runserver
```

После запуска веб-интерфейс будет доступен по локальному адресу:

`http://127.0.0.1:8000/`

Сервер `runserver` предназначен для локальной разработки и тестирования проекта.

## Веб-интерфейс

HelpDesk System содержит веб-интерфейс, реализованный средствами Django Templates и Bootstrap.

Для веб-интерфейса используется стандартная сессионная аутентификация Django. После входа пользователю предоставляются доступные ему возможности в соответствии с назначенной ролью.

Основные страницы системы:

| URL                  | Назначение                       |

Веб-интерфейс предусматривает работу с заявками, комментариями и статистической информацией, а также отображение доступных пользователю действий в соответствии с его полномочиями.

## REST API

HelpDesk System предоставляет REST API для программного взаимодействия с основными сущностями системы.

API реализован с использованием Django REST Framework.

Основные группы endpoint:

| URL                | Назначение                      |
| ------------------ | ------------------------------- |
| `/api/`            | Работа с пользователями         |
| `/api/tickets/`    | Работа с заявками               |
| `/api/comments/`   | Работа с комментариями          |
| `/api/statistics/` | Получение статистики по заявкам |

API поддерживает операции с заявками и комментариями, а также поиск, фильтрацию и сортировку данных в предусмотренных системой endpoint.

## JWT-аутентификация

Для доступа к защищённым REST API используется JWT-аутентификация на основе SimpleJWT.

Получение пары токенов:

```text
POST /api/token/
```

Обновление access-токена:

```text
POST /api/token/refresh/
```

При успешной аутентификации API возвращает `access` и `refresh` токены.

Для обращения к защищённым endpoint access-токен передаётся в HTTP-заголовке:

```text
Authorization: Bearer <access_token>
```

Таким образом, проект использует два механизма аутентификации:

* **Session Authentication** - для веб-интерфейса;
* **JWT Authentication** - для REST API.

## Документация REST API

Документация REST API формируется автоматически с использованием `drf-spectacular` и спецификации OpenAPI.

После запуска проекта доступны:

| URL                    | Назначение        |
| ---------------------- | ----------------- |
| `/api/schema/`         | OpenAPI-схема API |
| `/api/schema/swagger/` | Swagger UI        |
| `/api/schema/redoc/`   | ReDoc             |

### Swagger UI

Swagger UI предоставляет интерактивное представление API и позволяет просматривать доступные endpoint, параметры запросов и структуры ответов.

Для работы с защищёнными endpoint можно использовать JWT-токен через механизм авторизации Swagger UI.

### ReDoc

ReDoc предоставляет альтернативное представление OpenAPI-документации, предназначенное преимущественно для просмотра структуры и описания REST API.

## Email-уведомления

HelpDesk System поддерживает автоматическую отправку email-уведомлений при основных событиях жизненного цикла заявки.

Логика уведомлений зависит от текущего состояния заявки и роли получателя.

В частности, система предусматривает уведомления:

* менеджеров - о создании новой заявки;
* назначенного специалиста технической поддержки - о передаче заявки в работу;
* менеджеров - о заявках, требующих контроля или дополнительного вмешательства;
* автора заявки - о завершении её обработки.

Если в системе зарегистрировано несколько пользователей с ролью `Manager` и указанными адресами электронной почты, уведомление о новой заявке направляется всем таким менеджерам.

Для отправки сообщений используется SMTP. Параметры подключения задаются через переменные окружения и не хранятся непосредственно в исходном коде проекта.

Текущая реализация использует текстовые email-сообщения. В качестве возможного дальнейшего развития системы может быть реализована персонализация уведомлений и расширено оформление сообщений.

Цель разработки - исследование процессов обработки обращений технической поддержки и создание информационной системы, обеспечивающей регистрацию, распределение, обработку, контроль и анализ заявок пользователей.

Проект демонстрирует применение Python и Django для разработки информационной системы, включающей веб-интерфейс, REST API, ролевую модель доступа, работу с реляционной базой данных, автоматические уведомления, статистику и автоматизированное тестирование.
